# ZooApp
## Соответсвование требованиям
1. Классы доменной модели расположены в Domain.Entities, также там(в Domain) расположены:
	1. Базовый класс сущности именнуемый IUniqueId, 
	1. Enumы для описания сущностей (они не имеют практической значимости, по-хорошему стоило реализовать доменные модели использую только встроенные классы и ValueObjects), в данном случае выступают своеобразными ValueObjects.
	1. Базовые доменные события
	1. Интерфесы репозиториев, сервисов, обработчиков
	1. Базовый класс репозитория
2. Архитектура проекта построенна по Clean Architecture
	1. Зависимости направлены внутрь (от внешних слоев к ядру)
	1. Бизнес-логика изолирована в Domain и Application
	1. Гибкость
	1. Соблюдение разделения на Domain, Application, Infrastrusture, Presentation
3. В слое Web API реализован следующий функционал:
	1. CRD (без update) для Animals, Enclosures, Schedules 
	1. Контроллер кормления
	1. Контроллер транспортировки животных между вольерами
	1. Статистический котнроллер
4. Проведено тестирование функционала API через SwaggerUI
5. Хранение данных реализовано через InMemory Dictionary. Функционал репозиториев не зависит от классов, поэтому реализация прописана в BaseRepository.
